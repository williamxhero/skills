# Improve Codebase Architecture To Done

本目录是可审查的入口源码；STATIC 检查只验证源码结构，不证明实际 Pi 行为。本次源码变更未部署／未安装到 CC Switch；原生运行验收与经授权的 CC Switch 导入须另留证据，不能由源码存在推断能力已生效。

## 管理与执行前提

CC Switch 继续管理本机技能。源码仓库不改写其配置或客户端链接，不建立自动安装、双向同步或第二套任务调度。

每次进入先完整读取实际安装兄弟入口内的[共享工程规则](../to-spec-to-done/references/engineering-quality.md)和[自动推荐 grilling 适配](../to-spec-to-done/references/auto-grilling.md)。以实际加载的 SKILL.md 父目录为锚点解析相对路径，再用绝对路径读取；当前项目目录不是技能根。必须安装兼容的 `to-spec-to-done` 和 `implement-spec-to-done`，只复制本目录不会带来兄弟资源；缺失／不可读或版本不兼容即 blocked，不维护规则副本。只有调用方显式提供 skill root 才在该根定位，否则按共享规则解析实际安装兄弟技能，同名来源不明则 blocked。

读取真实 `SKILL.md` 及触发的必需参考并执行才算调用，没有 Skill API。预检实际 `improve-codebase-architecture`、`codebase-design` 和两个包装入口；上游 Matt 技能另由 CC Switch 管理，专项资源随实施入口交付。需要 fresh 探索及后续真实角色时，读取并执行[Pi 执行适配](../implement-spec-to-done/references/pi-execution.md)的能力探针与角色契约；不能运行必需角色即 blocked，启动响应不等于完成。记录依赖实际路径、版本／hash 与本地适配；不以记忆、同一上下文自扮探索或旧版入口冒充整合流程。

## C1 确定范围、授权与改进前基线

用户给定范围优先；否则从近期提交热点选择有限范围，变更分散也须记录本次扫描边界后再扩查。读取项目指令、权威术语、有关 ADR、历史经验、当前实现及测试；记录基线 commit SHA、工作树状态／相关未提交差异、环境、现有行为与测试命令／实际结果。把具体摩擦绑定到调用点、变更记录、失败或理解／修改／验证成本；未运行的测试明确标记，不能编造基线。扫描授权不自动成为发布、实施或任意范围重构授权。

完成条件：范围／非目标、授权边界、基线与可复查的摩擦证据明确；关键基线事实不可查则 blocked。

## C2 调用原架构技能的候选阶段

**LOCAL CANDIDATE-PHASE ADAPTATION**：完整读取实际 `improve-codebase-architecture/SKILL.md`，执行原第 1 步 Explore 和第 2 步可视候选报告；原第 2 步末尾的用户 pick 等待及原第 3 步 grilling 不执行，分别由 C3 自动推荐选择和 C4 规格入口承接。这是局部阶段执行，不报告为完整原版调用。原版不修改，单独调用仍保留其用户选择与交互 grilling。

读取真实 `codebase-design` 使用 module／interface／depth／seam／adapter／locality／leverage 词汇及原则，尊重项目领域术语。依 Pi 执行适配派发新上下文、只读、限定范围的探索子 Agent，传范围、基线、项目指令和领域记录指针；等待工具事件、调查输出及退出码，逐项核对其来源，不能只凭成功摘要。调查 shallow modules、修改分散、interface 泄漏、状态写入责任和难从公开 interface 测试的摩擦。

对每个候选应用 **deletion test**：删除该 module 后复杂度消失，还是其必要行为散落到多个 callers？分别说明哪些实现应删、哪些复杂度需集中保留以及证据，不以删除本身算收益。用具体调用点／修改路径说明 locality 如何集中变更与验证，leverage 如何减少调用者必须理解的 interface 成本；比较维持现状与更简单做法。只有一个 adapter 时不凭空添 seam。明确 ADR 冲突及值得重开的现实代价，不提前确定完整新接口。

候选卡包含涉及 modules／files 与来源、问题、拟议变化、预期收益及其验证办法、风险／兼容／恢复、推荐强度 `Strong`／`Worth exploring`／`Speculative`，结尾给出有据首选（没有则明说）。报告区分**现状事实**与**拟议／未实施**结构；已有实际改后证据才可称“After 实测”，预期接口不能标成已存在。

可视报告按实际所选路线执行，记录绝对产物路径和验证结果：

- 默认原 HTML 路线：先读实际原技能目录的 `HTML-REPORT.md`，使用其真实 scaffold／图示模式。按原规则写 OS temp 下唯一 `architecture-review-<timestamp>.html`，不写入项目；使用 Tailwind／Mermaid CDN 或手绘 CSS／SVG，打开文件并告知路径。核对 diagram 语法／实际呈现；CDN／浏览能力不足则明确未验证，必需图无法呈现时 blocked。
- 只有选择委托 `visual-explainer` 时，才读其实际正文及触发参考，按实际能力先 prepare 取得输出目录，再写源文件并 render；不能臆造命令或用文字替代成功产物。
- 每个候选均有 `Before（现状）`／`Proposed（拟议）` 图和事实／假设图例。无图不称已完成可视候选阶段。确实无候选时报告已调查范围和排除依据，无需制造虚构前后图。

完成条件：探索真实完成，候选报告与图可核对，收益来自实际成本而非图形美观或文件／行数／层数；必需事实或能力缺失则 blocked。

## C3 选择本次推荐候选或结束

在已授权范围内自动采用有事实支持、收益明确且风险可控的首选；默认只推进一个候选或有证据说明不可分的一组，不把全部建议当成已选范围。记录比较、推荐理由、未选原因、证据／假设和下一阶段需核验的收益。`Speculative` 不是自动实施许可，关键前提未证实不能自动推进；风险／收益未成立时先调查或排除，不拼凑大范围重构。

- **no-change**：已完成所需调查，范围／基线充分，候选因无实际摩擦、无足够收益或风险不值得而被排除；附来源和排除理由，以无代码变更正常结束。此路径不发布 SPEC、不拆票、不实施，也不进入 C4–C7。
- **blocked**：缺少关键事实、权限／授权或必需能力，尚不能可靠选择或推进。按共享规则记录具体阶段、已查结果、保留报告和最小继续条件；不是“没有收益”，不得伪装 no-change。只有扫描许可而没有发布／实施许可时，在相应行动前保留成果并报告所缺授权。
- **selected**：首选范围和依据明确，后续权限具备才进入 C4。恢复时先回读实际 SPEC／tracker、Git 与既有候选报告，核对基线和外部结果，复用有效证据；不从头重扫或重复发布。

完成条件：有据 selected，或有据 no-change 后停止；blocked 留在真实受阻阶段，不换候选绕过。

## C4 委托规格入口完成设计推敲与发布

读取并执行真实 `to-spec-to-done/SKILL.md` 及其必需参考，传入所选候选／报告、基线证据、目标／非目标、保留行为、范围、风险、约束和已有授权／决定。由它主持唯一的**规格级 grilling**，本次只在这一处执行，依已加载自动推荐适配调查事实并逐轮采用全部推荐；小任务／已有候选也不跳过。C2 不先做设计访谈，外层不重跑同一轮。重要接口／术语取舍由该入口按共享规则触发设计技能。

在规格发布前确定可核验收益：改前基线、观测方法／公开 seam、候选与环境绑定、成功阈值或定性判定依据，以及兼容行为、迁移顺序、失败恢复／回退路径和验证方法，均写入验收（不适用项写理由）。不把文件／行数／层数减少当通用成功指标，也不把预期收益称实测。仅由原 `to-spec` 按原模板生成并发布，外层不代行发布或维护模板。单候选通常一个 SPEC；真正独立验收边界才沿规格入口组织总／子 SPEC，不预建 tickets。

完成条件：规格入口已源头回读真实 SPEC 正文、验收、标签、必需原生关系及完整交付约定，收益／兼容／迁移／恢复已进入关闭前验收。发布或回读失败保留实际成果并 blocked；结果未知先查源头，不直接实施或重复创建。

## C5 源头核对交接与实施授权

接收规格入口的真实引用与回读证据，再源头回读 tracker 仓库／Issue 身份、完整正文、评论、状态、父子／阻塞关系及已有交付记录，不能只信链接或发布摘要。本仓库 GitHub 操作显式 `--repo williamxhero/skills`，API 用同仓库 endpoint；其他项目遵其实际 tracker 指令。核对候选范围／收益／验收和原授权是否一致、有无漂移，以及发布／实施／Git／关闭各行动是否获准。SPEC 发布不等于实施授权；自动推荐不扩权，越界或缺权限则保留 SPEC 并 blocked，不擅自继续。

`to-spec-to-done` 至此已按自身语义结束，由本外层继续明确获准的总任务。不重建 SPEC、不复制 tickets／原生任务图，不另设执行计划、任务状态或第三套实现器；既有合格 SPEC／tickets 由对应入口恢复复用。已交付 CLOSED 的同一 SPEC 核对证据后直接 C7，不重复实施；未关闭／未交付的按事实进入 C6。多 SPEC 交给实施入口按依赖保持唯一当前项，外层不并行调度。

完成条件：真实 SPEC 身份、范围、状态、验收与实施授权均核对成立；不符则停在本阶段并明确最小继续条件。

## C6 只委托实施入口交付当前改进 SPEC

读取并执行真实 `implement-spec-to-done/SKILL.md` 及其必需参考，仅传本次选中改进的 SPEC（或同一改进的总 SPEC 引用）、候选／基线证据与已核定完成方法，保持唯一当前 SPEC。不直接调用另一轮 to-tickets／implement-spec，不复制 B1–B12 调度或专项资源；由实施入口负责恢复、拆票、隔离 TDD、集成、稳定后简化、条件经验捕获、最终独立双轴审查、验收及 Git／tracker 交付。

其中 B3 必做实施现实／环境复核，复用 C4 的设计决定和已授权 seam，不重开重复设计访谈。其 B9 必须把收益前后对照、保留行为／兼容、迁移及失败恢复／回退在关闭前逐项验收；纯“测试没有变红”不足以证明改进收益。将证据及候选／环境写入实施入口的完成记录，B10–B11 全部交付门禁成立、记录回读后才能关闭；外层无权提前释放关闭、清理或自动关票。

完成条件：本次改进按 SPEC 的完整方法验收、主干集成和合并后验证、安全清理、正常 push／远端一致，完成记录回读并确认关闭。失败留在当前 SPEC 修复或报告 blocked，不换候选掩盖未交付，也不提前启动后续 SPEC。

## C7 回读已形成的交付证据并停止

实施入口关闭确认后源头回读交付提交／主干、tracking／真实远端、tracker `CLOSED` 和完成记录，以及关闭前已形成的收益、兼容、迁移与恢复证据。核对其候选、环境、基线和验收对应关系；C7 是回读，不是事后补验收，不能替代关闭前缺失的证明。若误关、证据缺失或候选／环境变化使证据过期，按授权恢复对应验证与真实状态，保留恢复点并报告未完成；不把 CLOSED 或旧报告当完成证明。

完成条件：选中改进已验证交付且记录与现实一致；报告范围、所选／未选候选、SPEC／提交／报告与证据指针、适配版本、实际收益和限制，区分 STATIC、实际 Pi、独立审查、CC Switch 导入及远端同步。C3 no-change 是另一条有据的正常终态，不虚构交付。到此结束，不自动重扫全仓、递归调用架构入口或追加下一轮重构。
