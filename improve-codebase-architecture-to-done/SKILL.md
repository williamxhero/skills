# Improve Codebase Architecture To Done

**状态：新增源码草案，尚未通过整合 SPEC 验收，也未安装到 CC Switch。** 本文件不代表已部署能力；现有两个包装入口仍是原样导出版本。实施、验证与经 CC Switch 导入后，才能把该技能报告为可用。

## 管理与执行前提

CC Switch 继续管理本机技能。源码仓库不改写其配置或客户端链接，不建立自动安装、双向同步或第二套任务调度。

执行前读取项目指令、用户范围和所用技能的实际 SKILL.md。依赖从 CC Switch 已管理的安装环境解析；本仓库未打包这些依赖。必需技能或独立探索／审查能力缺失时，保留已有成果并报告具体阻塞，不用近似流程冒充调用成功。

依赖入口至少包括 `improve-codebase-architecture`、`codebase-design`、`to-spec-to-done` 和 `implement-spec-to-done`。两个 To-Done 入口还必须已经满足整合 SPEC 中的自动推荐 grilling、专项检查与完整交付要求；不能对原样导出的旧入口假定新增行为已存在。

## 1. 确定范围与改进前基线

用户给定范围优先；否则先从近期变更热点限定调查。读取有关术语、ADR、历史经验、实现和测试，记录实际摩擦与已有行为。扫描授权不自动扩展为任意重构授权。

完成条件：调查范围、授权边界、现状及可复查证据明确。

## 2. 委托架构调查的候选阶段

读取并执行 `improve-codebase-architecture` 的调查与候选报告阶段，明确记录这是阶段适配：其内部调用 `codebase-design` 并使用新上下文探索子 Agent，输出有证据的问题、预期收益、前后示意和推荐强度。暂不重复执行原技能后续的设计 grilling，统一交给第 4 步。

报告区分现状与拟议结构，不提前把新接口标成已经存在。使用 visual-explainer 时先 prepare 取得输出目录，再写源文件并 render；使用原技能报告机制时遵循其实际参考要求。

完成条件：候选体现真实修改成本、理解成本或验证困难，而不只是抽象审美。

## 3. 选择本次推荐候选

在用户已授权范围内，自动采用有证据、收益明确且风险可控的首选；默认只推进一个候选或不可分割的一组，不把全部建议一起实施。

没有值得实施的候选时，记录依据并以 `no-change` 结束。缺少关键事实、超出授权或必要能力不可用时是 `blocked`，不是 `no-change`。

完成条件：选中范围与理由明确，或形成有依据的无需变更结论。

## 4. 委托规格入口完成设计推敲与发布

调用 `to-spec-to-done`，输入所选候选、证据、目标、现有行为、范围和限制。它必须实际调用 `grilling`，按决策依赖逐轮调查并自动采用全部推荐答案；不能以需求简单或已有候选为由跳过。按需调用 `codebase-design`、`design-an-interface` 和 `domain-modeling`，最后仅由 `to-spec` 生成和发布规格。

把行为保持、改进收益、兼容迁移、失败恢复、回退与验证方法写入验收。不把减少行数、文件数或层数当作通用成功指标。复用已形成的决定和授权，不等待常规逐题确认；推荐不代替事实或扩大外部行动许可。

完成条件：真实 SPEC 已发布，正文、完整交付约定及必需的原生关系回读通过。发布失败时停在本阶段，不直接实施。

## 5. 核对交接

接收真实 SPEC 标识，核对推敲后的范围仍符合原目标与授权。不复制任务图，不重新生成另一份 SPEC。规格入口按其自身语义已经结束，是本外层入口继续已授权的总任务。

完成条件：规格引用、验收与后续实施授权明确。

## 6. 委托实施入口交付

调用 `implement-spec-to-done`，仅输入本次改进 SPEC。复用唯一当前 SPEC、实施复核 grilling、`to-tickets`、`implement-spec`／`tdd`、`verification-before-completion`、稳定后的 `ce-simplify-code`、条件式 `ce-compound`、最终 `code-review` 和完整 Git／tracker 交付闭环。

改进收益必须在关闭前验证。失败留在当前 SPEC 修复或报告阻塞，不换候选掩盖未完成。所有子技能受当前范围、证明测试、关闭与安全清理门禁约束。

完成条件：所选改进按约定验收、主干集成、验证、清理、推送并核验远端，完成记录回读后才关闭。

## 7. 回读结果并停止

核对交付提交、主干、远端、Issue 状态以及关闭前形成的收益和兼容证据。候选或环境变化导致证据失效时恢复对应核验，不把旧证据算作当前结果。

完成条件：所选改进真实交付，或第 3 步有依据地判定无需改进。报告完成范围、证据和限制后结束；不自动重扫全仓或追加下一轮重构。
