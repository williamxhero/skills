# 共享工程规则

这是三个 To-Done 包装入口的单一工程规则来源，随 `to-spec-to-done` 目录交付；它是参考，不是独立技能、调度器或第二份任务状态。其他包装入口在相应阶段读取本资源；实际流程仍由各入口主持。

## 资源定位与真实调用

- 以**实际加载的入口 SKILL.md 的父目录**为锚点，解析入口内相对资源；使用工具所需的绝对路径读取。当前工作目录不等于技能目录。
- 本入口加载 `references/`；其他入口从其安装目录的兄弟目录 `../to-spec-to-done/references/engineering-quality.md` 和 `../to-spec-to-done/references/auto-grilling.md` 加载。CC Switch 必须安装 `to-spec-to-done` 整个目录；仓库之外的 `_shared` 不会随单目录复制交付。
- 上游技能先从实际安装的兄弟技能目录 `<name>/SKILL.md` 解析。只有调用方**确实显式提供技能根（skill root）**时，才可在该根定位；不猜环境变量、用户路径或额外全局目录。跟随已存在的 CC Switch 链接可以读取实际目标，不更换客户端链接。
- 同名多版本或路径含糊时核对实际加载来源，仍不能唯一确定则 blocked。记录实际路径、版本／提交或内容哈希及适配差异；固定来源不是永远正确的兼容保证。
- 读取实际技能正文及分支触发的必需参考并执行，才算调用；没有虚构的 Skill API。此安装忽略 `disable-model-invocation`，它不是拒绝委托的理由；不因此更改上游元数据或全局交互。
- 资源缺失、依赖不可读、必需子 Agent 不可用或平台能力不满足时，停在受阻阶段并报告 blocked；保留成果，不以记忆、手工近似或自审冒充必需调用。

## 事实、决定与授权

读取项目指令、相关实现与测试、既有 SPEC／tickets、术语、ADR 和相关经验。分别记录可查证的事实、已确定决定、假设与未知，附必要来源。调查能查清的事实；推荐只能选择方案，不能把假设变成事实。

复用已有决定、明确约束和已授权的公开测试接口（seam）；新事实影响它们时，记录修订理由及受影响依赖。实质变更测试接口或范围须取得适用授权，不为测试泄露内部实现。已有术语和 ADR 是权威；术语变化或重要取舍成立才调用 `domain-modeling`，按需更新原记录，不另养冲突词表。

自动采纳推荐只替代常规选择与重复确认，不扩大业务授权。调查、设计、发布、实施、付费、删除、安装和不可逆动作分别核对权限；完全访问或 Bypass permissions 本身不等于这些外部行动已获许可。用户暂停立即生效。

## 比例适当的设计检查

按实际风险检查每项，简单任务可简短注明现状或不适用理由：

- 目标、非目标、真实约束，以及可开工的首个可验收切片。
- 模块职责、接口调用成本、复杂度封装、修改局部性；状态权威来源、写入责任和一致性。
- 关键成功与失败路径、幂等、重试、恢复、兼容迁移及可观测性。
- 公开测试接口、已有先例、验收及证据；区分静态、模拟、真实执行与平台回读。

只有重要接口存在真正不同方案时才调用 `design-an-interface`；若其必需独立子 Agent 无法运行，报告阻塞而非假装完成比较。新增抽象、服务、队列、缓存或插件须有实际问题，比较更简单做法，注明暂缓机制与升级触发条件；吞吐扩展不等于能力可修改性。

Superpowers brainstorming / writing-plans 的目标澄清、约束比较、小切片与可验证计划仅作经本地适配的**参考方法**；不声称完整调用，不引入第二套批准、文档、执行器交接。需要真实专项调用的阶段仍加载实际技能，不用这些方法替代。

## 证据与恢复

SPEC 管目标、验收和确定设计；tickets 及原生依赖管实现任务图；代码／配置管实际机制，术语／ADR／经验各守职责。执行记录只存阶段、指针、版本、决定和证据，不维护第二个任务图或可执行状态机。

恢复先核对受影响的实际 tracker、工作树、分支、提交及远端状态；只处理本任务明确归属的成果和资源。按故障性质处理：

- 授权内的定位、显示或解析错误：保留原失败，由 Agent 修复并只重验受影响证据；不为同一授权内工作再请批准，也不追认原失败为通过。
- Issue 创建、push 等外部写入结果未知：先向实际 tracker 或远端核对身份、内容及是否已生效，再决定是否重试；保留部分成果，不盲重试或重复写入。
- 越界读取、授权缺失、实质验收冲突，或必需证据仍不可得：停止相关动作并报告缺项；不把安全问题称作显示故障，不换分支掩盖失败。

常规记录留候选、命令、结果及证据指针，不逐层复制全量日志。分别报告 STATIC、文本推演、模拟、实际 Pi、独立审查、Git／远端交付、CC Switch 导入及实际加载。源码存在不代表部署，部署不证明加载；静态或推演不证明模型执行。

阻塞报告包含：当前阶段、缺少的具体事实／能力／权限、已查证结果、保留成果、最小继续条件和下一步。关键事实不可验证时保留 blocked；非关键假设须有风险界限和验证安排，不能把阻塞包装成推荐。
