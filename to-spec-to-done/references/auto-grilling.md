# Wrapper-local 自动推荐 grilling 适配

每次规格入口都读取并执行实际安装的 `grilling/SKILL.md`，再按本适配运行；实施入口在每个当前 SPEC 拆票前复核时同样适用。定位、调用与阻塞规则见同目录 `engineering-quality.md`。此适配不修改原版 `grilling`，单独调用原版仍保留其交互方式。

与上游的差异：保留 design tree、frontier、逐轮推荐与事实调查；按共享 To-Done 默认决策，把原版的逐轮等待答题与末尾共享理解确认替换为 Agent 采纳并记录，不索要首次 opt-in。权限模式本身不构成业务授权；不伪造用户答复。事实调查依上游派发新上下文子 Agent，必需能力缺失则按共享规则 blocked；运行中的调查仍是未决前提，其下游等待，其余 frontier 可继续。

## 每次必跑，沿依赖收敛

1. 将本次目标与已有决定整理为 design tree。即便需求小、明确、信息完整，也执行 grilling 理解复核；不以简单为由跳过，不设置问题数、轮数或篇幅下限。已经确定的决定直接复用，不为形式重问。
2. 计算本轮 frontier：只纳入前置事实和决定已经成立的问题。本轮仍待回答的问题不能充当同轮其他问题的前提。调查事实、标注来源；无法验证的事实仍是未知，不编推荐答案填空。
3. 对整个可处理 frontier 按上游问题／推荐格式给出简明结论与重要依据。按共享规则自动采用本轮相容推荐（互斥时只选有据首选），记录决定、假设、验证安排及实际行动授权，不等待常规逐题回复或末尾“再确认”。不展示冗长内部推理。
4. 采纳后重算 frontier，再推进下一轮。新证据推翻旧推荐时修订决定、依赖及受影响设计；不固守旧答案，也不重启无关访谈。
5. frontier 为空且影响首个可验收切片的设计项都已处理，才进入规格就绪检查。重要未知有验证方案且不阻止开工可显式保留；关键未知或授权不足则 blocked，保留已完成轮次和最小继续条件，不等待虚假的常规确认，也不带着阻塞发布成完整规格。

每轮只保留可审查记录：问题／前置条件、事实来源、推荐与已采纳决定、重要理由、未验证假设及验证安排。它是决定摘要，不是第二份调度状态。实现复核复用规格级结果，集中检查环境变化、设计漂移和实施风险。
