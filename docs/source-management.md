# CC Switch 管理与 GitHub 源码归档

## 不变的安装链

```text
CC Switch 管理源：~/.cc-switch/skills/<name>
        ↓ CC Switch 原有分发与链接
各客户端技能目录（包含 Pi）
```

`D:/WILL/AGENT/skills` 是用户指定的独立 Git 源码仓库，不替换上面的链路。初次导出只复制既有文件，保留客户端链接和 CC Switch 设置。第三个技能此前不存在，因此仓库只保存未安装草案。

## 后续更新

1. 在本仓库按 SPEC 开发、审查并保存版本。
2. 经授权后使用 CC Switch 支持的导入／更新路径，把选定版本交给 CC Switch 管理。
3. 检查 CC Switch 管理源和客户端实际加载内容、链接及依赖。
4. 将源码提交、导入版本与真实验证结果分别记入交付证据。

如果 CC Switch 中存在更新，先比较并合并到对应源码版本，再决定导出；不盲目双向覆盖，不增加第二个自动同步进程。

## 依赖定位

本仓库只收录三个包装入口，不复制全部上游技能。现有导出文件中的兄弟技能链接是安装环境依赖，不表示它们已经被 vendored 到本仓库。实际执行时必须在 CC Switch 管理的技能环境解析并读取依赖；完整依赖清单、可移植定位和运行前检查属于整合 SPEC 的交付要求。

## 发布不等于部署

源码已提交或 Issue 已创建，只证明归档／任务记录成立。强制 grilling、专项简化、经验回写和最终审查顺序等拟增强行为，在实现与真实验证之前都不能报告为已生效。
