## Reproduction boundary

Use a fresh independent external fixture working directory and process for each case, not this source repository or a real application. Copy the three candidate entry directories and the actual required Matt dependencies into one isolated staging root; retain per-file hashes and supply that root explicitly. Do not copy over installed skills. To test missing-resource behavior, use a separate root omitting the named shared dependency; do not repair it by falling back to globals.

Resolve `$PiExecutable` to the actual native Pi CLI, `$Entry` to an absolute candidate entry directory, and `$Provider` / `$Model` / `$Thinking` to the authorized runtime settings; retain exact values externally. On the observed Windows host the native CLI was `pi.cmd`, version 1.5.2, not pi-web. From the fixture cwd:

```powershell
& $PiExecutable --no-extensions --no-mcp --no-skills --skill $Entry --no-prompt-templates --provider $Provider --model $Model --thinking $Thinking --tools read,powershell,grep,find,ls --no-session --mode json $SkillCommand
```

`$SkillCommand` begins with `/skill:<entry-name>` plus the bounded request. Add write/edit tools only for explicitly authorized local publication fixtures. All shell tools can write: an allowlist is not a security sandbox. Restrict scope in fixture instructions, inspect tool calls and actual diffs, prohibit GitHub/network writes, installed-resource/config/link changes, push, closure and unrelated paths. In these bounded fixtures, permit only the required child roles (read-only fact explorers, including an explicitly configured startup-failure case), not final independent reviewers. Outer specialist/source reviews are separate native processes, not claims made by a fixture parent. Verify each child’s actual cwd, new session identity, tools, output and exit separately.

Use stdlib subprocess or native child_process to stream stdout/stderr to external files, wait with a finite timeout and preserve exact argv/cwd/exit. Split JSONL on LF, not Unicode separators; PowerShell 5 redirection may require lossless UTF-16→UTF-8 conversion. Inspect authoritative `message_end`, `agent_settled.aborted`, error/retry events AND exit code. Exit 0 alone does not imply success in JSON mode. `toolUse` interim messages are normal; final error/aborted/length, missing settled, timeout or parse errors are never a pass. Even a clean transport only proves the run finished; inspect tool evidence, persisted state and requirement-specific outcome separately. A truthful blocked outcome passes only the failure contract, not the workflow's completion criteria.
