# 研究过程经验合同

每次使用本技能都产出一份独立 Markdown，沉淀本次研究中已验证、可迁移、能改变未来行动的经验。它是研究交付物，不是聊天复述、运行日志或策略绩效报告的附录。

## 生命周期

1. 冻结策略/研究身份并确定 owning project 后，先读该工程的 `AGENTS.md` 和文档分类规则，再确定唯一文件路径。默认使用 `<project>/docs/reports/<strategy-id>-研究过程经验总结-<YYYY-MM-DD>.md`；工程规则另有要求时服从工程规则。
2. 同一次研究工作、迁移或 incident 的恢复、身份演进与 retry 复用原文件，并记录 package/revision/request/run/study 的变化原因；只有研究目标或范围实质分叉时才新建文件，并在新旧文件中互相引用。
3. 恢复中断任务时，先读已有经验文件，再用当前聊天、任务摘要、Git 历史、immutable objects、日志和 artifacts 补齐后续证据。聊天记忆只提供线索。
4. 在以下边界当场审查 lesson 候选并更新文件：规格冻结、Package 验证、live preflight、数据修复、正式 run、Research publication、Reporting、长任务监督、发布收尾。
5. 最终验收回顾当前任务可用的完整对话历史与全部阶段证据，补漏、逐条重验并去重；将仍无证据的内容保留为“待验证候选”，不得写成确定规则。

## Lesson 证据门

一条正式 lesson 必须同时满足：

- **有证据**：能指向本次任务中的 artifact、日志、测试、计时、diff、公开 CLI/API 对象或可复现实验。
- **有机制**：说明为什么发生；根因尚不确定时明确写为观察性经验，并给出验证条件。
- **可迁移**：能转化为下次研究的具体决策、检查或操作，而不只是描述本次发生了什么。
- **有边界**：说明适用组件、数据形态、研究阶段和例外，避免把局部结论泛化成全局规则。
- **有价值**：至少减少一次常见失败、一次昂贵重跑、一类错误结论，或提升速度、确定性、可审计性与交付质量。

进度时间线、普通命令清单、未经验证的推测、单纯策略盈亏、泛泛而谈的最佳实践，以及只对一个临时路径成立的事实不进入正式 lessons。失败尝试只有在其失败机制、恢复办法和触发条件已被证据支持时才收录。

## 文件结构

```markdown
# <strategy-id> 研究过程经验总结

- 研究身份：<package/revision/request/run/study>
- 研究范围：<本文件覆盖的阶段>
- 更新时间：<ISO date/time>
- 状态：active | completed | blocked

## 可直接复用的结论

- <最重要的行动规则；链接到下方 lesson>

## 已验证 Lessons

### L001 <动作导向标题>

- 阶段：<identity | data | runtime | research | reporting | operations | release>
- 观察与证据：<事实、数值、对象 ID、测试或文件链接>
- 根因/机制：<为什么>
- 可复用规则：<未来应遵循什么>
- 下次操作：<触发条件下的具体步骤或检查>
- 适用边界：<适用与不适用范围>
- 影响：<节省时间、避免重跑、提高确定性等；能量化则量化>

## 待验证候选

- <观察、缺少的证据、验证办法；没有则写“无”>

## 已审查但无新增经验的阶段

- <阶段、日期、审查依据>
```

按 lesson 的价值组织内容，不按聊天发生顺序抄写。标题使用动作导向表述，例如“在创建 run 前遍历 terminal cursor”，不要写成“遇到了一次超时”。

## 完成门

交付前确认：文件独立存在且路径符合工程规则；研究身份与最终对象一致；每条正式 lesson 都通过证据门；证据引用可访问且不泄露凭证、私有数据库或敏感 payload；重复经验已合并；任务最终回复提供可点击路径。没有新增 lesson 时仍保留研究身份、已审查阶段和明确的零新增结论。
