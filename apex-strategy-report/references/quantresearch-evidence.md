# 证据与研究边界

## 资料冻结与可执行规格

将文章、文档、聊天或 legacy 项目证据冻结为可追溯来源。每条内容分为：

- `source evidence`：原作者明确的规则、参数、标的、范围、成本和指标；
- `legacy evidence`：旧代码、配置、产物或报告所证明的实际旧运行语义；
- `research assumption`：运行必需但资料未说明的决定。

建立唯一可执行规格，至少包含宇宙、频率、adjustment、信号与 warm-up、决策/成交时点、规模、风险控制、进入/退出、成本/滑点/保证金、初始资金、日历、数据范围与策略参数。缺失的决定性选择必须进入不可复现差异，不能静默猜测。

## 形式化结果的证据

正式结果只能引用由 Nautilus 原生生成并经 Workspace 发布的 account、orders、fills、positions、statistics、reporting input 及 frozen run identity。与 legacy 比较时列出共同与不同项：数据范围、数据版本、调整语义、时间/日历、成本、订单/成交、账户会计和指标定义。

方向性接近不等于一比一复现；旧指标永远是来源对照，不能复制到新报告或用于补缺指标。

## Apex Research decision

protocol/trial/evidence/decision 应说明每道 gate 的对象和结果。`accept` 仅接受已定义证据门，不表示可交易、通过样本外、稳健性、容量、相关性或未来收益验证。

未满足任一前提的能力必须写 `not_evaluated`，包括但不限于：

- OOS / walk-forward / 参数敏感性；
- 历史 PIT 行业、基本面、风格或基准归因；
- 费用/滑点压力与市场冲击；
- 容量、流动性与实盘可成交性；
- 无原生明细支持的产品级 PnL、因果归因或集中度结论。

不要从展示层推导指标，不要将审计日志中的局部数据外推为组合或全样本结论。

## 不可复现与数据变化

无一比一复现时，报告清楚标明差异来源、预期偏向及其对结论的影响，但不把推测写成事实。历史费用或保证金没有 PIT 资料时，冻结资料只能被称为单一 profile，而不是历史真实成本。

市场数据、catalog、calendar、query、配置或 snapshot identity 变化会形成新的研究身份。旧研究仍绑定旧证据；不要覆盖历史报告或将新数据混入旧结果。
